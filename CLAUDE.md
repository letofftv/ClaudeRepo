# ClaudeRepo — хранилище находок для домашней фабрики

Сюда владелец приносит новинки (репозитории, плагины, навыки, MCP-серверы, видео
с советами), которые хочет дать Claude. Здесь их **разбирают и оценивают**, а не
устанавливают: это безопасная песочница перед тем, как что-то попадёт на фабрику.

Каждая облачная сессия начинается без памяти о прошлых — всё, что нужно знать,
записано в этом файле и в индексах направлений (`<направление>/README.md`).

## Структура — по направлениям (с 2026-10-27)

| Папка | Направление |
|---|---|
| `video/` | Видеомонтаж: монтаж, запись экрана, субтитры, озвучка роликов, апскейл |
| `animation/` | Анимация и мультипликация: моушн-графика, рендер кодом, ИИ-картинки и видео, 3D |
| `audio/` | Аудио и мастеринг: музыка, сведение, мастеринг, вокал, DAW; пакет `audio/packs/music-studio` |
| `coding/` | Программирование и вайбкодинг с Claude Code |
| `productivity/` | Организация работы: задачи, заметки, документы, календарь, почта |
| `business/` | Цифровизация бизнеса: автоматизация, CRM, продажи, аналитика, боты |
| `common/` | Общее: безопасность находок, настройка сервера, сборки общего назначения |

В каждом направлении: `README.md` (индекс: лучшее, находки со статусами,
пробелы), `finds/` (карточки), `research/` (отчёты). Корневой `README.md` —
карта для владельца. `app/` — приложение «Домашний пульт» (см. ниже). `handoff/` — канал в фабрику (пути там не менять:
ссылки уже переданы), `templates/finding.md` — шаблон карточки.
Находка, которая подходит нескольким направлениям, лежит в одном (основном),
а в индексах остальных — ссылка на неё.

## Фабрика

- Производит: ролики, клипы, анимацию, обучающие видео с интерфейсами
  существующих платформ (записи экрана, разборы UI).
- **Ролики не монетизируются** — модели с некоммерческими лицензиями (CC-BY-NC
  и т.п.) допустимы. Если начнётся монетизация или работа на клиента/бизнес —
  пересмотреть все такие находки (они помечены в карточках и в research).
- **Озвучка — на русском.**

### Сервер

- Xeon E3-1230 v3 (4 ядра / 8 потоков, 2013, AVX2 есть), **16 ГБ ОЗУ**,
  видеокарта **GTX 1050 Ti (Gigabyte Windforce), 4 ГБ**. SSD 512 ГБ (~370
  свободно), HDD 1 ТБ (~440 свободно).
- Сейчас **Windows 10 Pro + WSL2 (Ubuntu) + Docker**: видеокарта в контейнерах
  через CUDA, Chromium — через мост D3D12. WSL2 по умолчанию получает
  половину ОЗУ (8 из 16 ГБ), если не задано в `.wslconfig`. Владелец планирует
  переезд на **Ubuntu**.
- Уже работает: **Whisper large-v3 на видеокарте** (таймкоды слов), Ollama
  (только эмбеддинги), Postgres + pgvector, Redis, ферма рендера, линия
  нарезки клипов, «руки» агента Джарвиса.
- Часть загрузок (сайт NVIDIA, некоторые модели) напрямую с сервера
  недоступна — их качают через мак. Для находок с большими моделями
  учитывать, откуда их скачать.

### Мак — рабочее место Claude

- MacBook Pro M1 Pro, 16 ГБ, ~48 ГБ свободно. Рендер кадра 1080×1920 через
  Metal ~0,3 с — **самый быстрый рендер фабрики**. Локальная диффузия
  возможна, но медленно. Apple Vision даёт маски и точки лица и тела.
- В карточках отмечать, где инструмент лучше запускать: на сервере или на маке.

### Джарвис

- Агент на слабом VPS без видеокарты; модели через подписку ChatGPT; общение
  через Telegram; отправляет задания на ферму. Есть ли у него генерация
  картинок или видео через API — не проверено.

### Ферма видео (своя)

- Сцены пишутся кодом (HTML, SVG, Canvas, WebGL) и считаются покадрово в
  Chromium; ffmpeg собирает ProRes или H.264; для Premiere — XML. Задания — с
  мака или от Джарвиса.
- Инструменты: таймкоды слов (Whisper), сетка долей музыки, маски и точки
  лица/тела (Apple Vision), отделка и автопроверка «лука».
- Скорость: ферма на CPU ~2,6 с/кадр на воркер (3 воркера); WebGL на
  видеокарте 6,6 мс/кадр против 221 мс на CPU, но целая сцена ~8,5 с/кадр
  (не хватает видеопамяти); мак ~0,3 с/кадр.
- Сильные стороны: моушн-графика, инфографика, обучающие ролики по
  интерфейсам, точный синхрон под голос и музыку, монтаж, компоновка, титры.
- **Потолок** (проверено 25–26.10, три попытки отвергнуты): живописные
  персонажи, узнаваемое лицо и живописная среда уровня референсов кодом не
  достигаются. **Это главный пробел, который должны закрывать находки.**
- Находки, повторяющие ферму (HTML → кадры → ffmpeg: HyperFrames, Remotion,
  product-launch-motion), оценивать как **источник приёмов и блоков**, а не
  как замену — критерий «Пересечения».

### Текущий проект — клип «Город пробок»

- WAV 3:39,2, 48 кГц; разметка вокала (68 строк, 371 слово, сверена
  владельцем); сетка долей 89,4 уд/мин; бриф V3 на 34 сцены, дизайн-код в
  JSON, референсы, фото на хромакее; 9:16, 1080×1920, 24 к/с (~5 260 кадров).
- Упирается в потолок фермы: нужны живописные сцены и узнаваемое лицо.

### Музыка и звук (с 2026-10-27)

- Владелец сочиняет музыку, сводит, мастерит и записывает русский вокал под
  готовые минусовки. Проекты некоммерческие.
- Для этого собран пакет Claude Code **`audio/packs/music-studio`** (7 навыков,
  справочники, скрипты замеров на ffmpeg); ставится из этого репозитория
  как плагин (`claude plugin marketplace add letofftv/ClaudeRepo`).
  Исследование — `audio/research/2026-10-27-audio-production.md`.
- Находки по звуку оценивать и для мака (Apple Silicon: MPS, CoreML, MLX;
  только нативные плагины — Rosetta уходит).
- Покупка у западных вендоров из России затруднена — к платным позициям
  указывать бесплатный аналог; пиратство не рассматривать.
- **Ableton Live 12 Suite, версия 12.4.7** → основной MCP — Producer Pal
  (нужна 12.3+ — подходит). Max for Live, Roar, Hybrid Reverb, Stem
  Separation есть.
- **Вокал записывается на студии** (профессиональные звуковая карта и
  микрофон, бренды неизвестны); **на маке — только сведение и мастеринг**.
  Студия работает в **Ableton и Cubase**: из Ableton — сет через «Collect
  All and Save», из Cubase — сухие WAV 48 кГц / 24 бит пакетным экспортом
  каналов от начала проекта (навык `vocal-recording`).

### Ограничения видеокарты — учитывать при каждой оценке

- Архитектура Pascal (GP107, compute capability 6.1): нет тензорных ядер,
  FP16 на этом чипе фактически не ускоряется, bf16 нет. Модели, которым нужны
  FlashAttention, bf16 или свежий CUDA 13, здесь не пойдут.
- Драйверы NVIDIA ветки 580 — последние для Pascal; CUDA 12.x — последняя
  версия CUDA. **PyTorch — только сборки cu126 и не новее 2.14** (2.15 бросает
  Pascal; cu128 — с 2.8). Никогда не ставить torch строкой из README как есть.
  Docker-образы брать под CUDA 12, не `:cuda13`.
- Предпочитать инструменты **без PyTorch** (C++/GGML, ncnn/Vulkan, ONNX) — они
  переживут уход PyTorch с Pascal.
- На Ubuntu — только проприетарный `nvidia-driver-580` из репозитория Ubuntu
  (не `-open`: открытые модули Pascal не поддерживают; не .run-установщик).
  На Linux нет подкачки видеопамяти в ОЗУ — нехватка 4 ГБ = падение, на
  Windows — медленно, но работает. Подробно:
  `common/research/2026-10-26-ubuntu-gpu-setup.md`.
- Аппаратное кодирование NVENC есть (H.264, HEVC) — рендер HyperFrames с
  `--gpu` работает. Основной конвейер (HTML → видео, запись браузера) от
  видеокарты почти не зависит.
- Современное генеративное ИИ-видео на 4 ГБ недоступно (реально — только
  AnimateDiff-петли и слабый LTX-Video 2B); озвучка, субтитры, апскейл,
  интерполяция, картинки SD1.5 — доступны. Подробно:
  `video/research/2026-10-26-local-voice-and-video.md`.

Пока неизвестно (уточнить у владельца, когда будет к месту, и дописать сюда):
какой именно Whisper работает (whisper.cpp, faster-whisper…), использует ли
ферма GSAP или другие библиотеки анимации, как сейчас снимаются интерфейсы
для обучающих роликов, какая версия Ubuntu планируется, есть ли у Джарвиса
генерация картинок/видео через API.

## Домашний пульт (`app/`, с 2026-10-27)

Личное приложение владельца: веб-интерфейс + JSON API на сервере и MCP-мост
для Claude Code на маке. Только стандартная библиотека Python 3.9+, на сервере
нужен ffmpeg. Подробно — `app/README.md`.

- `app/hub/` — сервер. Токен (`HUB_TOKEN`), задачи в фоне, рабочая папка с
  `inputs/` и `jobs/<id>/out/`, каталог собирается из markdown этого
  репозитория.
- `app/config/tools.json` — реестр инструментов. Это шаблоны argv без shell,
  у параметров типы и проверки. Пути конкретного сервера хранятся в
  `tools.local.json`, его нет в git.
- `app/data/free-resources.json` — бесплатные ресурсы для контента.
  `common/free-resources.md` генерируется скриптом
  `app/scripts/render_resources.py`: правки вносить в JSON.
- `app/data/starter-sets.json` — стартовые наборы и команды установки. При
  смене статусов в индексах направлений обновлять и его.
- `app/mcp_bridge.py` — MCP-мост на стандартной библиотеке.
- Тесты: `cd app && python3 -m unittest discover -s tests`. Прогонять после
  каждой правки `app/`.
- Находка, которую удобно запускать с сервера, — кандидат в инструменты
  пульта: добавить в `tools.json` с `requires` и тестом.
- Не проверено на настоящем сервере (2026-10-27): NVENC, whisper, sd,
  video2x, audio-separator, scenedetect, auto-editor. Когда владелец запустит
  пульт, записать сюда, что заработало.

## Как оценивать находку

1. **Польза для продукции** — какой тип роликов это улучшает и чем именно.
2. **Работа без человека** — CLI, headless-режим, API лучше, чем GUI-программа.
   Использует ли видеокарту, если задача на неё ложится.
3. **Пересечения** — не держать два инструмента под одну задачу; если находка
   дублирует уже выбранное, сравнить и оставить одно.
4. **Лицензия** — можно ли использовать для роликов, в том числе коммерчески.
5. **Безопасность** — официальный ли источник; есть ли хуки, выполнение
   сгенерированного кода, отправка данных наружу. Код хуков читать до вывода.
6. **Вес для агента** — сколько агентов/навыков/хуков добавляет в каждую сессию.
   Брать нужные части, а не «установить всё».

## Как работать с находкой

- Владелец кидает ссылку → определить направление → карточка
  `<направление>/finds/<slug>.md` по шаблону `templates/finding.md` + строка в
  таблице `<направление>/README.md` → коммит и пуш.
- Широкий поиск по теме → отчёт `<направление>/research/<дата>-<тема>.md` +
  карточки только на то, что стоит пробовать.
- Свои пакеты навыков (плагины Claude Code) — в `<направление>/packs/<имя>/`
  и запись в `.claude-plugin/marketplace.json`; проверять
  `claude plugin validate`.
- Чужие репозитории клонировать только во временную папку (scratchpad),
  не в этот репозиторий. Ничего не устанавливать без прямой просьбы.
- Перед установкой навыка на фабрику — прогнать его через SkillSpector
  (`common/finds/skillspector.md`).
- Статусы: **взять** · **попробовать** · **позже** · **отклонено**.
- В карточке честно разделять: что проверено руками, а что взято из README.

## Передача в фабрику

Фабрику клипов разрабатывает другой Claude (на маке); прямой связи между
сессиями нет. Канал — `handoff/`: пакет для фабрики кладётся туда, владелец
вставляет в её диалог текст со ссылкой на raw-файл (шаблон —
`handoff/README.md`). Каждый пакет заканчивается разделом «Ответ для
песочницы»; когда владелец пересылает ответ сюда — записать факты в этот файл
и в карточки.

## Ветки

Все находки собираются в `main`. Сессия работает в своей ветке `claude/...`,
а в конце работы вливает её в `main` (fast-forward или обычный merge, без
переписывания истории) и пушит `main` — владелец разрешил это 2026-10-26,
чтобы карточки не расходились по веткам. Перед началом работы подтянуть
свежий `main`.

## Приватность

Репозиторий **публичный**. Не записывать сюда ключи, пароли, адреса и имена
серверов, личные данные — только сами находки и оценки.
