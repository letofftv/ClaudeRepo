## Промпт

Ты — оператор домашнего сервера (тот же, что ведёт «Домашний пульт», см.
`~/hub-ops/CLAUDE.md`). Владелец переезжает с Windows 10 + WSL2 на
Ubuntu Server 24.04 на отдельном SSD; Windows и WSL остаются как откат.
План переезда:
https://raw.githubusercontent.com/letofftv/ClaudeRepo/main/common/ubuntu-migration/README.md
— прочитай его первым.

Твоя задача сейчас — **подготовить всё, ничего не ломая**: опись, замеры
«до», резервные копии на HDD и список того, что придётся скачать на маке.
На новой Ubuntu тот, кто будет восстанавливать (скорее всего, ты же, но
без памяти этой сессии), должен поднять всё только по твоим файлам.

### Правила

1. **Ничего не останавливать и не удалять.** Исключение — короткая пауза
   для согласованного дампа, если служба иначе не даёт целую копию.
   Спросить владельца заранее.
2. **В Windows ничего не менять.** Быстрый запуск, BitLocker и BIOS
   владелец делает сам — ты только сообщаешь, что нужно.
3. **Секреты:**
   - файлы `.env`, токены и ключи копировать как файлы, с правами 600;
   - содержимое не печатать и не вставлять в отчёты;
   - адреса и имена машин не попадают в «Ответ для песочницы».
4. Если места на HDD не хватает или что-то неясно — спросить, а не
   выбрасывать данные.

### Шаг 1. Опись

```
mkdir -p ~/hub-ops/migration
curl -fsSL https://raw.githubusercontent.com/letofftv/ClaudeRepo/main/common/ubuntu-migration/inventory.sh -o ~/hub-ops/migration/inventory.sh
bash ~/hub-ops/migration/inventory.sh > ~/hub-ops/migration/inventory-$(date +%F).md
```

Прочитай отчёт целиком. Чего в нём нет, а нужно, — допиши руками (как
запускается ферма, откуда Джарвис шлёт задания, где модели Whisper).

### Шаг 2. План переноса — `~/hub-ops/migration/plan.md`

По одной строке на каждую службу и задачу — ферма, Whisper, Postgres +
pgvector, Redis, Ollama, линия нарезки клипов, «руки» Джарвиса, пульт и
всё, что найдёшь:

| Служба | Как запущена сейчас | Где данные | Как перенести | Как запускать на Ubuntu | Порты | Кто к ней ходит |
|---|---|---|---|---|---|---|

- **Как перенести** — одно из:
  - скачать образ заново;
  - `docker save` (образ собран локально — в описи «ЛОКАЛЬНЫЙ»);
  - дамп базы;
  - копия файлов.
- **Как запускать на Ubuntu** — compose с `restart: unless-stopped` или
  пользовательская служба systemd.
- **Windows-часть** — отдельными строками, у каждой укажи, чем её
  заменить на Ubuntu:
  - задача планировщика, держащая WSL, → не нужна;
  - `portproxy` и правила брандмауэра → `ufw`;
  - свои службы Windows.
- В конце — порядок восстановления: сначала базы, потом то, что от них
  зависит.

### Шаг 3. Замеры «до»

Те же замеры повторятся после переезда — запиши условия, чтобы их можно
было повторить точь-в-точь:

- **ферма** — одна эталонная сцена: секунд на кадр и пик видеопамяти;
- **пульт:**
  - `whisper` на тех же 5 с вокала;
  - `stems` на тех же 15 с;
  - `vertical_9x16` на том же ролике — видеокарта и «только процессор»;
- `nvidia-smi` в простое — занятая видеопамять.

### Шаг 4. Резервные копии на HDD

Папка `<HDD>/migration-<дата>/`. HDD смотри в описи (`/mnt/<буква>`).
Сначала проверь свободное место.

- **Postgres:**
  - `pg_dumpall` из контейнера → `postgres.sql.zst`;
  - рядом записать точный тег образа и версию расширения pgvector;
  - проверить архив: `zstd -t`.
- **Redis:** если включено сохранение — `BGSAVE`, затем копия
  `dump.rdb` / `appendonly`; если это только кэш — так и записать.
- **Docker:**
  - образы «ЛОКАЛЬНЫЙ» (в том числе Whisper фабрики):
    `docker save <образ> | zstd > images/<имя>.tar.zst`;
  - именованные тома, кроме базы: `tar` через вспомогательный контейнер,
    в том числе кэш моделей Whisper;
  - compose-файлы и их папки целиком, с `.env`.
- **Ollama:** список моделей. Каталог моделей копировать, только если он
  небольшой, — иначе скачать заново.
- **Ферма, линия нарезки, «руки» Джарвиса:**
  - папки кода и настроек целиком;
  - в описи отметить репозитории с незакоммиченными правками. Ничего не
    коммитить, просто скопировать.
- **Пульт:**
  - `~/ClaudeRepo/app/config/hub.json`, `tools.local.json`,
    `~/.config/hub/env`;
  - `~/hub-work/models` (модели audio-separator, голоса Piper);
  - `~/hub-ops` целиком.

  `~/hub-work/jobs` — по желанию владельца.
- **Система:**
  - `~/.ssh/authorized_keys` — чтобы ключ мака сразу работал;
  - `crontab -l`;
  - свои юниты systemd.
- **Проверка копий:**
  - `sha256sum` всех файлов → `SHA256SUMS`, размеры → `SIZES`;
  - на HDD — короткий `README.md`: что где лежит и чем восстанавливать.

### Шаг 5. Что придётся качать на маке

Проверь с сервера, открываются ли (`curl -sI -m 10`):

- download.docker.com;
- nvidia.github.io — репозиторий NVIDIA Container Toolkit;
- registry-1.docker.io, ghcr.io;
- pypi.org, download.pytorch.org;
- github.com, objects.githubusercontent.com;
- huggingface.co;
- archive.ubuntu.com.

Закрытые — в отчёт со списком, что владельцу скачать на маке:
- `.deb` пакеты Container Toolkit;
- образы через `docker save` на маке;
- голоса Piper и т. п.

### Шаг 6. Отчёт

1. **Владельцу коротко:**
   - что сохранено и сколько места заняло;
   - что из Windows ему сделать: BitLocker, `powercfg /h off`;
   - режим загрузки: UEFI или Legacy;
   - что скачать на маке;
   - вопросы.
2. **Блок для песочницы**, без адресов, имён и секретов:

```
Ответ для песочницы — подготовка к переезду, <дата>
Режим загрузки Windows: UEFI/Legacy; Secure Boot: вкл/выкл/неизвестно; BitLocker: да/нет; быстрый запуск: был вкл/выкл
Docker: Docker Desktop / свой движок в WSL; контейнеров N; локально собранных образов N (какие)
Службы и как запущены сейчас: <список: служба — compose/systemd/задача Windows — данные>
Резервные копии: <что, объём>, проверены: да/нет
Замеры «до»: ферма <с/кадр, сцена>; whisper <с>; stems <с>; vertical_9x16 GPU/CPU <с>
Закрыто с сервера: <адреса>
Что неясно / вопросы: <...>
```
