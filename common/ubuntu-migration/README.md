# Переезд сервера на Ubuntu (второй SSD)

План на 2026-10-28. Сейчас сервер работает на Windows 10 + WSL2 (Ubuntu
24.04.5) + Docker. Переезжаем на Ubuntu на отдельном SSD, Windows на
старом SSD остаётся как откат. Про видеокарту — подробно в
[исследовании](../research/2026-10-26-ubuntu-gpu-setup.md).

## Решения

- **Ubuntu Server 24.04 LTS, ядро GA 6.8, без HWE.** Server-образ по
  умолчанию ставит ядро GA, а HWE в 24.04.5 — это уже Linux 7.0.
  - На 7.0 есть сообщения, что драйвер 580 не собирается.
  - Готовые модули 580 для ядра 6.8 давно проверены.
  - Версия совпадает с WSL, поэтому привычки и пакеты те же.
- **Без графической оболочки.** Вся видеопамять достаётся ферме, не
  рабочему столу. Управление — по SSH с мака и через пульт.
- **Двойная загрузка, Windows не трогаем.** Ubuntu целиком ставится на
  новый SSD, старый SSD с Windows и WSL остаётся как был. Если что-то
  не так — загрузиться в Windows, и всё работает по-старому.
- **Перенос через HDD.** Службы не копируются как есть: их поднимают
  заново по описи. Данные (база, образы, модели, настройки) идут через
  резервные копии на HDD. WSL не удалять недели две, пока Ubuntu не
  отработает.
- **Драйвер:** только проприетарный `nvidia-driver-580` из репозитория
  Ubuntu. Не `-open` (Pascal он не поддерживает), не `.run`, без CUDA
  Toolkit на хосте.

## Что меняется к лучшему и что проверить

- **Плюсы:**
  - вся ОЗУ (16 ГБ вместо 8 у WSL);
  - нативный драйвер для Chromium и WebGL фермы;
  - Vulkan, а с ним Video2X;
  - nvidia-smi отдаёт питание и память по процессам;
  - не нужны проброс портов Windows → WSL и задача, которая держит WSL.
- **Риск 1 — видеопамять не подкачивается в ОЗУ.** То, что в WSL
  «влезало» медленно, на Linux падает. Пульт в этом случае пересчитает
  задачу на процессоре; ферме нужно проверить свои тяжёлые сцены.
- **Риск 2 — WebGL фермы без экрана.** Chromium должен найти видеокарту
  через EGL. Это проверяет Claude фабрики, пакет для него — в `handoff/`.
- **Риск 3 — смена адреса.** Джарвису, маку и мосту MCP нужно вписать
  новый адрес сервера.

## Порядок

### 0. Сейчас, до приезда — Claude на сервере (WSL)

Вставить в Claude Code на сервере (из `~/hub-ops`):

> Прочитай и выполни
> https://raw.githubusercontent.com/letofftv/ClaudeRepo/main/common/ubuntu-migration/prompt-before.md

Он сделает опись, замеры «до» и резервные копии на HDD, проверит, какие
загрузки с сервера закрыты, и пришлёт отчёт со списком вопросов. Службы
не останавливаются, работа идёт ~1–2 ч.

### 1. В Windows — руками, ~15 мин

1. **BitLocker.** Если он включён (видно в отчёте шага 0), сохранить ключ
   восстановления. После смены порядка загрузки Windows может его
   спросить.
2. **Быстрый запуск и гибернация.** Выключить: в консоли администратора
   `powercfg /h off`. Иначе Ubuntu увидит диски NTFS «грязными» и не
   даст писать на HDD.
3. **Режим загрузки.** Посмотреть в отчёте шага 0: UEFI или Legacy.
   Ubuntu ставить в том же режиме.

### 2. На маке — флешка, ~15 мин

1. Скачать образ **Ubuntu Server 24.04 LTS** (`ubuntu-24.04.x-live-server-amd64.iso`)
   с releases.ubuntu.com или с зеркала mirror.yandex.ru/ubuntu-releases/.
2. Записать на флешку от 4 ГБ, например balenaEtcher или
   `sudo dd if=<iso> of=/dev/rdiskN bs=4m` (диск — по `diskutil list`).

### 3. Установка — руками, ~40 мин

1. **Поставить SSD.** Надёжнее всего на время установки отключить SSD с
   Windows и HDD. Тогда установщик не тронет чужой загрузчик, а у Ubuntu
   будет свой. Если отключать неудобно — в установщике выбирать диск
   строго по размеру и модели.
2. **Загрузиться с флешки** в том же режиме, что Windows (UEFI или
   Legacy). Видеовыход — с GTX 1050 Ti, встроенной графики у Xeon нет.
3. **В установщике:**
   - тип — Ubuntu Server, не minimized;
   - диск — весь новый SSD, LVM можно оставить;
   - профиль — имя сервера и пользователь;
   - **OpenSSH server — включить**;
   - сторонние драйверы не искать, их поставит Claude;
   - snaps (в том числе docker) — не ставить.
4. **Подключить диски обратно.** В BIOS первым поставить SSD с Ubuntu.
   Windows — через меню выбора загрузки.
5. **Secure Boot** не трогать. Если при установке драйвера Ubuntu попросит
   пароль MOK, после перезагрузки на синем экране выбрать «Enroll MOK» и
   ввести его.

### 4. Первый вход — руками, ~10 мин

1. На сервере узнать адрес: `ip -br a`. В роутере закрепить его за
   сервером.
2. С мака: `ssh-copy-id <пользователь>@<адрес>`, затем `ssh` без пароля.
3. Поставить Claude Code и войти. Создать `~/hub-ops`, в нём запустить
   `claude` и вставить:

> Прочитай и выполни
> https://raw.githubusercontent.com/letofftv/ClaudeRepo/main/common/ubuntu-migration/prompt-after.md

### 5. Claude на сервере (Ubuntu)

По `prompt-after.md`, по шагам с вашими «да»:
- драйвер и перезагрузка;
- диски и Docker с видеокартой;
- восстановление Postgres, Redis, Ollama, Whisper, фермы и «рук» Джарвиса;
- пульт с прежними настройками и токеном;
- проверка и замеры «после».

### 6. Переключение

- **Джарвис** — новый адрес фермы.
- **Мак** — адрес в `~/.ssh/config` и `HUB_URL` моста MCP; токен тот же.
- **Фабрика** — пакет `handoff/2026-10-28-ubuntu-migration.md` вставить в
  её диалог по шаблону `handoff/README.md`.
- **Песочница** — «Ответ для песочницы» прислать сюда.

## Откат

Меню загрузки → Windows: всё работает как раньше, WSL не тронут.
Ubuntu на втором SSD при этом просто не запускается, ничего не
конфликтует. Если Ubuntu уже обработала задания, новые данные (база,
результаты) остаются на её диске и в резервных копиях на HDD.

## Что известно не до конца

- Объём второго SSD. Для системы, Docker, образов и моделей хватит от
  250 ГБ.
- Как запущены ферма и «руки» Джарвиса, где их данные — это даст опись
  на шаге 0.
- Открыты ли с сервера download.docker.com и nvidia.github.io (репозиторий
  Container Toolkit). Если нет, пакеты качаются на маке, шаг 0 это
  проверит.
- Работает ли драйвер 580 на ядре 7.0. Поэтому и берём GA 6.8.
