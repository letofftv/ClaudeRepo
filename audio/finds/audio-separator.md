# python-audio-separator

- **Ссылка:** https://github.com/nomadkaraoke/python-audio-separator
- **Что это:** CLI и Python-библиотека для разделения трека на стемы и вокал (модели UVR, RoFormer, ансамбли)
- **Найдено:** 2026-10-27, исследование открытых инструментов
- **Статус:** **взять** (стоит на сервере, инструмент пульта `stems`)

## Зачем фабрике

- Стемы из минусовки — тонкая правка под вокал (опустить середину бита,
  поправить бас), когда битмейкер не дал стемов.
- Чистый вокал — для таймкодов текста и разбора чужих референсов.
- Модели для вокала: де-реверб, шумоподавление, «Aspiration» (вдохи),
  отделение бэк-вокала.
- Качество: лучшие RoFormer-модели ~11,3 SDR вокал / ~17,5 SDR
  инструментал (уровень лидеров открытых моделей).
- **Где запускать:**
  - сервер, видеокарта: PyTorch 2.14.1+cu126, в 8 раз быстрее процессора
    (замер ниже);
  - мак: MPS и CoreML.

## Риски и оговорки

- Код MIT, у моделей лицензии разные (часть — некоммерческие; для фабрики
  допустимо).
- **PyTorch с PyPI на этой карте не годится.** Сборка по умолчанию — под
  свежую CUDA без Pascal, поэтому torch ставить отдельно из индекса cu126,
  не новее 2.14 (правила карты — в `CLAUDE.md`). Когда PyTorch бросит
  Pascal, на сервере останется процессор или BSRoformer.cpp (GGML).
- На Apple Silicon нужен PyTorch ≥ 2.13.
- **Модели качаются с GitHub-релизов**, не с Hugging Face — удобно при
  блокировках загрузок. Папка по умолчанию — `/tmp/audio-separator-models/`,
  её чистит система, поэтому `--model_file_dir` указывать на постоянную
  папку.
- Разделение даёт артефакты — основой микса оставлять оригинал.
- Опциональный удалённый API использует Modal — не включать.

## Как подключить

**Сервер (видеокарта)** — по отчёту оператора, команды собраны в
песочнице:

```
sudo apt install -y build-essential python3-dev    # только на время установки: diffq собирается из исходников
pipx install "audio-separator[cpu]==0.47.1"         # [cpu] — onnxruntime для ONNX-моделей; RoFormer идёт на PyTorch
pipx runpip audio-separator install "torch==2.14.1" --index-url https://download.pytorch.org/whl/cu126
pipx inject audio-separator audioread               # 0.47.1 его не объявляет
sudo apt remove -y build-essential python3-dev && sudo apt autoremove -y   # по желанию
```

- **Без видеокарты** torch брать из `https://download.pytorch.org/whl/cpu`,
  иначе pip притащит CUDA-сборку на несколько гигабайт.
- **В пульте** — инструмент `stems`:
  - модели лежат в папке `separator_models`, по умолчанию
    `<рабочая папка>/models/audio-separator`;
  - сначала считается на видеокарте, при сбое — на процессоре с
    `CUDA_VISIBLE_DEVICES=""`.

**Мак:** по навыку `audio-toolkit` пакета `audio/packs/music-studio`.
Список моделей — `audio-separator --list_models --list_format=json`.

## Что проверено

- **Оператором на сервере** (2026-10-28, через API пульта):
  - 0.47.1 с PyTorch 2.14.1+cu126 на GTX 1050 Ti;
  - 15 с трека моделью по умолчанию: на видеокарте 35 с, на процессоре
    4 мин 53 с (на `main` по умолчанию — BS-RoFormer; какая модель была в
    замере, оператор не указал);
  - пик видеопамяти ~3 ГБ из 4;
  - через пульт 0.4.0 — 42 с на 15 с трека вместе с загрузкой модели;
  - **нехватка видеопамяти не роняет задачу:** при 3,5 ГБ, занятых другим
    процессом, разделение досчиталось на видеокарте за 17 с вместо 10 —
    в WSL драйвер Windows сбрасывает излишек в обычную память. На Ubuntu
    без WSL такая нехватка — падение, и пульт пересчитает задачу на
    процессоре.
- **В песочнице:**
  - код и README прочитаны;
  - по исходникам сверены флаги `--model_file_dir`, `--output_dir`, выбор
    устройства (`CUDA_VISIBLE_DEVICES=""` переводит на процессор) и
    зависимости (`[cpu]` и `[gpu]` — только onnxruntime).
- На маке не запускалось.
