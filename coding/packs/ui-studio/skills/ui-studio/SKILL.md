# Создатель интерфейсов

Цикл из шести шагов. Каждый шаг оставляет файл-результат, по которому видно,
что он сделан. Не перепрыгивать к коду: самые дорогие ошибки интерфейса —
в сценариях и навигации, а не в CSS.

| Шаг | Навык | Результат |
|---|---|---|
| 1. Кто и зачем | `ux-scenarios` | `design/ux.md`: участники, сценарии, частота, критерии успеха |
| 2. Экраны | `ux-scenarios` | там же: карта экранов, навигация, состояния каждого экрана |
| 3. Визуальная система | `visual-system` | `tokens.json` → `tokens.css` (контраст проверен скриптом) |
| 4. Сборка | `ui-build` | страницы на наборе `kit/` (ES-модули, без сборки, строгий CSP) |
| 5. Живые данные | `dashboard-panels` | плитки, графики, тревоги, свежесть данных |
| 6. Проверка | `ui-review` | `ui_check.mjs`: снимки телефон/компьютер × светлая/тёмная, 0 FAIL |

## Инструменты пакета

Все пути — относительно папки этого пакета (`coding/packs/ui-studio/` в
ClaudeRepo или каталога установленного плагина):

- `scripts/scaffold.py new <папка> --title "…"` — новый проект: оболочка с
  навигацией, роутер, токены, копия набора. `sync`/`check` — обновить копию
  набора или проверить, что она не разошлась с оригиналом.
- `scripts/tokens.py spec.json --out tokens.css` — светлая и тёмная темы из
  оттенка акцента; яркость подбирается до прохождения WCAG; отчёт по каждой паре.
- `scripts/ui_check.mjs --url … --routes …` — проверка в Chromium: переполнение,
  ошибки JS и CSP, контраст текста, размеры касания, подписи, alt; снимки и отчёт.
- `scripts/build_icons.py` — добавить иконки Lucide в спрайт `kit/icons.svg`.
- `kit/` — `base.css`, `components.css`, `ui.js`, `charts.js` (uPlot), иконки,
  `gallery.html` — витрина всех компонентов.

## Правила, которые действуют на всех шагах

- **Сначала частые сценарии.** То, что делают каждый день, — в один-два
  касания с первого экрана; редкое — глубже. Главный сигнал (всё ли в
  порядке) виден без прокрутки на телефоне.
- **У каждого экрана пять состояний:** загрузка, пусто, ошибка, нет связи
  или данные устарели, норма. Пустое состояние подсказывает следующий шаг.
- **Телефон — полноправный экран.** Нижняя панель ≤5 пунктов, касания ≥44 px,
  без горизонтальной прокрутки, нижние листы вместо модальных окон.
- **Текст интерфейса — по-русски**, глаголами на кнопках («Загрузить», а не
  «Загрузка»), с единицами через неразрывный пробел (`references/copy-ru.md`).
- **Цвет не единственный носитель смысла:** статус = цвет + иконка + слово.
- **Безопасность:** данные в DOM только через `textContent`/`el()`, без
  `innerHTML`; без внешних CDN; строгий CSP (`default-src 'self'`).
- **Проверка — скриптом, а не на глаз.** Контраст — `tokens.py`, вёрстка —
  `ui_check.mjs`; потом посмотреть снимки самому (Read по PNG).

## Как начинать

1. Прочитать, что уже есть: существующий интерфейс, API, ограничения среды
   (CSP, офлайн, кто пользователь, с каких устройств).
2. Если проекта нет — `scaffold.py new`; если есть — встроить набор через
   `scaffold.py sync <проект>/kit` и переводить экраны по одному.
3. Пройти шаги 1–6. После каждой заметной правки — `ui_check.mjs`.
4. В конце — короткий отчёт владельцу: что изменилось для его сценариев и
   снимки ключевых экранов.
