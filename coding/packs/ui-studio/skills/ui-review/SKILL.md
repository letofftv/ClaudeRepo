# Проверка интерфейса

## 1. Автопроверка

```
node scripts/ui_check.mjs --url http://127.0.0.1:8787/ \
  --routes "#/,#/server,#/jobs" --storage-json hub-token=<токен> --out ui-report
node scripts/ui_check.mjs --serve ./site --routes "index.html"     # статический сайт
```

Нужен Playwright (`npm i -g playwright && npx playwright install chromium`)
или готовый Chrome: `--channel chrome` / `--browser /путь`. По умолчанию —
телефон 390 px и компьютер 1366 px, светлая и тёмная тема.

| Уровень | Что ловит |
|---|---|
| FAIL | горизонтальная прокрутка, ошибки JS, нарушения CSP, 4xx/5xx своих запросов, контраст текста ниже WCAG, кнопки/ссылки/поля без подписи, картинки без alt, касание <24×24 px |
| WARN | касание <44×44 px на телефоне, шрифт <12 px, нет h1, нет `<html lang>` |

`--axe` подключает axe-core (если установлен) для полного аудита доступности.
Код выхода 1 при FAIL — можно ставить в тесты.

## 2. Посмотреть глазами

Открыть снимки (`ui-report/*.png`, Read показывает картинку) и проверить то,
что скрипт не видит:

- главный сигнал экрана заметен за 2 секунды; на телефоне — без прокрутки;
- иерархия: заголовок → ключевые цифры → детали; нет «стены одинаковых карточек»;
- выравнивание по сетке, одинаковые отступы, нет обрезанных подписей;
- тёмная тема — не перевёрнутая светлая: нет белых пятен, тени не грязные;
- состояния: пусто, загрузка, ошибка, устаревшие данные выглядят продуманно.

## 3. Ревью по фазам

Идти по порядку, каждая фаза — со своими снимками:

1. **Взаимодействие:** частые сценарии из `design/ux.md` по шагам; сколько
   касаний и переходов, где теряется контекст.
2. **Размеры экрана:** телефон 390, планшет 768–820, компьютер 1366–1440.
3. **Отделка:** выравнивание, отступы, иерархия, обрезанные подписи.
4. **Доступность:** Tab по всему экрану, видимый фокус, ловушка фокуса в
   диалогах, Esc, подписи.
5. **Устойчивость (стресс-состояния):**
   - пусто, 1 элемент, ×10 элементов;
   - одно слово и одна длинная строка без пробелов;
   - длинные русские слова («переподключающиеся»);
   - числа ru-RU (1 234,5);
   - нет сети, ошибка сервера, медленный ответ.
6. **Консоль:** ошибки JS, CSP, 4xx/5xx — их ловит `ui_check.mjs`.

Эвристики — `references/ux-heuristics.md`.

## 4. Договор о ревью

- Сначала перечислить, что будет проверено. Непроверенное в отчёте — «не
  проверено», а не замечание.
- У каждого замечания — место (экран, элемент или `файл:строка`) и
  сценарий, который оно ломает.
- Важность: **Блокер** (ломает сценарий, FAIL) · **Высокая** · **Средняя** ·
  **Мелочь**.
- Не больше 15 замечаний плюс 2–5 «рассмотрено и отклонено». Описывать
  проблему, а не готовое решение.
- Итог: «Нельзя выпускать» / «Нужны правки» / «Можно выпускать». Ревьюер
  ничего не правит сам; лучше всего ревью делает свежий субагент.

## 5. Исправить и повторить

Порядок: блокеры и FAIL → то, что ломает частые сценарии → WARN → вкус.
После правок — снова `ui_check.mjs` и снимки. Не больше трёх кругов, за круг —
три главные проблемы. В отчёте владельцу — до/после и 1–2 снимка ключевых
экранов.
