# Домашний пульт

Личное приложение, которое связывает мак, телефон и Claude Code с домашним
сервером. Оно запускает на сервере инструменты для аудио, видео и генерации,
даёт загрузить исходники и забрать результаты. В него же упакованы каталог
находок этого репозитория, бесплатные ресурсы для контента и стартовые наборы
навыков.

Пульт написан на Python 3.9+ и использует только стандартную библиотеку:
зависимостей нет, `pip install` не нужен. На сервере обязателен только ffmpeg.
Остальные инструменты пульт находит сам, если они есть в PATH. Недостающие
он показывает серыми и пишет причину.

```
браузер (мак, телефон) ─┐                       ┌─ ffmpeg, скрипты music-studio
                        ├─ HTTP + токен ─ пульт ─┼─ auto-editor, Whisper, стемы, NVENC…
Claude Code на маке ────┘  (VPN/дом)   (сервер)  └─ рабочая папка: inputs/, jobs/<id>/out/
   └─ mcp_bridge.py
```

## Что умеет

Интерфейс (0.3) собран пакетом [ui-studio](../coding/packs/ui-studio/README.md)
по сценариям из [`design/ux.md`](design/ux.md). Пять разделов: на телефоне —
нижняя панель с кнопкой «+» в центре, на компьютере — боковая. Отдельно —
настройки. Светлая и тёмная тема; можно добавить на главный экран телефона.

| Раздел | Что там |
|---|---|
| **Обзор** | итог одним словом («Всё в порядке / Есть замечания / Есть проблемы») и тревоги с временем; плитки ресурсов со спарклайнами; готовность видеокарты к тяжёлой задаче; идущие задачи с процентами; свежие результаты; быстрые действия |
| **Сервер** | живая панель (обновление раз в 3 с, пауза в скрытой вкладке): процессор по потокам, память и подкачка, видеопамять, загрузка и температура GPU, диски (включая `/mnt/c`, `/mnt/d` в WSL), сеть, диск I/O; история 15 мин / 1 ч / 6 ч / 24 ч на uPlot с таблицей у каждого графика; службы и контейнеры Docker; топ процессов по ЦП и памяти; версия и обновления; ссылки на Beszel/Dozzle |
| **+ Запуск** | бросить файл в любое место окна или выбрать — пульт предложит инструменты под тип файла; все инструменты с поиском и группами; файлы |
| **Задачи** | результат первым: отчёт громкости и сравнение с референсом — карточками с цифрами и оценкой, медиа — плеером; «Дальше →» запускает следующий инструмент на результате; прогресс и оценка времени у ffmpeg; лог свёрнут; повторить, удалить, очистить старые |
| **Библиотека** | каталог находок (112), бесплатные ресурсы (115, с доступом из России и лицензией), стартовые наборы — один поиск |
| Настройки | тема, версия и «Обновить сейчас», место под задачи, выход |

### Панель «Сервер»: что настраивается

Работает без настройки: процессор, память, диски, сеть, видеокарта
(nvidia-smi), контейнеры (если пользователю пульта доступен `docker`),
процессы. Тревоги поднимаются по порогам:

| Что | Замечание | Проблема |
|---|---|---|
| свободно на диске | <10 % или <30 ГБ | <5 % или <10 ГБ |
| доступная память | <20 % | <10 % |
| подкачка | ≥25 % | ≥60 % |
| процессор, среднее за 5 мин | >90 % (если идёт задача пульта — только справка) | — |
| температура GPU | ≥80 °C | ≥87 °C |
| видеопамять | ≥90 % | ≥97 % |
| служба | 1–2 неудачные проверки | 3 подряд |
| OOM в ядре | — | сразу |

В `config/hub.json` можно добавить:

```json
{
  "services": [
    {"name": "Postgres", "tcp": "127.0.0.1:5432"},
    {"name": "Ollama", "http": "http://127.0.0.1:11434/api/version"},
    {"name": "Ферма", "docker": "имя-контейнера"},
    {"name": "Whisper", "systemd": "whisper.service", "user": true},
    {"name": "Джарвис-руки", "process": "имя-процесса"}
  ],
  "disks": ["/mnt/d"],
  "links": [{"title": "Beszel — история за 30 дней", "url": "http://<адрес>:8090"}],
  "alerts": {"vram_warn_pct": 85, "disk_warn_gb": 50}
}
```

История за сутки (поминутно) сохраняется в `<рабочая папка>/metrics/` и
переживает перезапуски. Имена процессов берутся только из
`/proc/<pid>/comm`, без командных строк, в которых бывают токены.

### Видеокарта и откат на процессор

У инструментов с пометкой «видеокарта» в форме есть поле «Где считать»
(в API — параметр `device`):

- **Видеокарта, при сбое — процессор** (`auto`, по умолчанию). Сначала
  идёт вариант для видеокарты; если он упал, та же задача повторяется на
  процессоре. В логе появляется строка «Видеокарта не справилась…», в
  карточке задачи — «на процессоре (видеокарта не справилась)».
- **Только видеокарта** (`gpu`) — без отката, чтобы проверить саму карту.
- **Только процессор** (`cpu`) — когда важен размер файла.

Если nvidia-smi на сервере нет, задача сразу идёт на процессоре, а под
полем написано почему.

Замеры на сервере (GTX 1050 Ti, 2026-10-28):

| Что | Видеокарта | Процессор |
|---|---|---|
| Кодирование живого видео 1080×1920 при одинаковом качестве (SSIM 0,9925 и 0,9922) | 1,6 с, 11,6 МБ | 7,2 с, 7,9 МБ |
| `vertical_9x16`, 30 с 1080p | 9,0 с | 12,6 с |
| `burn_subtitles`, 30 с 1080p | 5,5 с | 13,5 с |
| `auto_editor_cut`, 30 с 1080p | 3,1 с | 9,1 с |
| `contact_sheet`, ролик 3 мин | 3,9 с | 5,8 с |
| `stems`, 15 с трека | 35 с, пик видеопамяти ~3 ГБ | 4 мин 53 с |

- **Размер файла.** NVENC на Pascal при `-cq`, равном CRF, даёт качество
  x264, но файл крупнее на ~45 %. Для публикации, где важен размер, —
  «Только процессор».
- **auto-editor.** С NVENC — только с `-b:v`, иначе файл втрое больше.
- **Короткие ролики.** На них контактный лист с видеокартой медленнее
  на 0,5 с: уходит время на запуск CUDA.

## Запуск на сервере

Проще всего поручить установку Claude Code на сервере. Готовый промпт —
[`deploy/server-prompt.md`](deploy/server-prompt.md): осмотр сервера,
установка, автозапуск, автообновление, проверка, отчёт. Вручную:

```
git clone https://github.com/letofftv/ClaudeRepo.git ~/ClaudeRepo
cd ~/ClaudeRepo/app
cp config/hub.example.json config/hub.json
export HUB_TOKEN="$(python3 -c 'import secrets; print(secrets.token_urlsafe(24))')"
echo "$HUB_TOKEN"        # сохранить в менеджер паролей
python3 -m hub --config config/hub.json
```

Если `HUB_TOKEN` не задан, пульт печатает временный токен, который действует
до перезапуска. Рабочая папка по умолчанию — `~/hub-work`, её можно сменить
в `config/hub.json` или переменной `HUB_WORKDIR`. Там лежат загрузки
(`inputs/`) и задачи (`jobs/<id>/` с `log.txt`, `job.json` и `out/`). В WSL2
её лучше держать на диске Linux: папки `/mnt/<диск>` медленные для видео.

- **Сейчас, Windows + WSL2.** Запускать внутри Ubuntu в WSL. С самого
  Windows пульт открывается по `http://localhost:8787`, потому что WSL
  пробрасывает localhost.
- **Автозапуск и автообновление.** Пользовательские службы systemd из
  `deploy/` (Ubuntu или WSL с `systemd=true`), порядок — в шапке
  `deploy/hub.service`. Токен лежит в `~/.config/hub/env`, а не в
  командной строке.
- **Docker.** Описан в разделе [Docker](#docker) ниже.

### Обновления

Таймер `hub-update.timer` раз в час запускает `deploy/update.sh`:

1. подтягивает свежий `main`;
2. гоняет тесты;
3. если тесты прошли — перезапускает пульт;
4. если нет — откатывает клон, и пульт остаётся на прежней версии. Эту
   версию обновлятор больше не пробует, пока в `main` не появится следующая.

Итог виден на вкладке «Сервер» в карточке «Версия пульта». Обновить
вне очереди можно инструментом «Обновить пульт сейчас». Новый интерфейс
применяется вместе с кодом: достаточно обновить страницу.

Если новой версии нужно что-то на самом сервере (программа, переменная,
настройка), это записано в [`CHANGELOG.md`](CHANGELOG.md) в разделе
«На сервере». Claude на сервере выполняет такие шаги по команде
«обнови пульт».

Обновлятор останавливается, если в клоне правили файлы из git. Свои
настройки сервера держать только в файлах вне git: `config/hub.json`,
`config/tools.local.json`, `~/.config/hub/env`.

### Пути к Whisper, озвучке и генерации

`config/tools.local.json` в git не попадает, в нём лежат пути конкретного
сервера. Пример — `config/tools.local.example.json`. В этом файле можно:

- задать переменные (`vars`):
  - путь к `whisper-cli` и модели;
  - адрес сервера озвучки (omnivoice.cpp, qwentts.cpp или обёртка Silero
    с `POST /v1/audio/speech`);
  - путь к `sd` и модели;
  - папки моделей audio-separator (`separator_models`) и голосов Piper
    (`piper_voices`).

  В значениях работают `~` и `{workdir}` (рабочая папка пульта);
- заменить у любого инструмента команду (`command`), параметры и `requires`;
- выключить лишние инструменты (`disable`);
- добавить свои инструменты.

**Whisper не из whisper.cpp** подключается через обёртку
`app/tools/whisper_subs.py`. Это faster-whisper, whisper-ctranslate2 или
свой Docker-образ. Что делает обёртка:

1. запускает движок (его команда идёт после `--`);
2. сама добавляет флаг языка (`--lang-flag=--lang`), а при «auto» не
   передаёт ничего, и движок определяет язык сам;
3. делает SRT и VTT из JSON, который движок оставил в `{out}`;
4. длинные отрезки режет по таймкодам слов: до 84 знаков и 7 с, две
   строки по 42.

Пример для Docker — в `config/tools.local.example.json`. Папку пульта
монтировать в контейнер по тому же пути, тогда пути внутри совпадут.

**Piper** (`tts_piper`) — лёгкая озвучка без сервера.

1. Поставить: `pipx install piper-tts`.
2. Скачать голоса. Голос — это пара файлов `.onnx` + `.onnx.json` в
   папке `piper_voices` (по умолчанию `<рабочая папка>/models/piper`):

   ```
   ~/.local/share/pipx/venvs/piper-tts/bin/python -m piper.download_voices ru_RU-irina-medium --data-dir ~/hub-work/models/piper
   ```

   Голоса лежат на Hugging Face. Если с сервера он не открывается —
   скачать оба файла на маке и скопировать.
3. Выбрать голос. Русские: irina, denis, dmitri, ruslan, все среднего
   качества. Абзацы разделяются паузой, переносы строк внутри абзаца
   склеиваются.

Ключ API сервера озвучки, если он нужен, задаётся переменной окружения
`TTS_API_KEY` при запуске пульта. В файлы его не записывать.

### Свой инструмент

```json
{
  "id": "my_tool",
  "title": "Название",
  "group": "audio | video | generation | system",
  "description": "Что делает",
  "command": ["программа", "{input}", "--level", "{level}", "{out}/result.wav"],
  "params": [
    {"name": "input", "type": "file", "label": "Файл", "required": true},
    {"name": "level", "type": "number", "default": 3, "min": 1, "max": 9, "integer": true}
  ],
  "requires": ["программа"],
  "timeout": 3600
}
```

Типы параметров:

- `file` — путь внутри рабочей папки; голое имя (`song.wav`) — файл из
  `inputs/` (как после `PUT /api/files/song.wav`);
- `number` — с границами `min` и `max`;
- `choice` — значение из списка `choices`; `labels` — подписи вариантов в
  форме;
- `string` — с `pattern` и `max_length`;
- `text` — длинный текст, его пульт сохраняет в файл и подставляет путь к нему.

Встроенные подстановки: `{out}` (папка результатов задачи), `{job}`, `{repo}`
(корень репозитория), `{python}`, `{workdir}` (рабочая папка).

Вариант для видеокарты задаётся блоком `gpu`, поле «Где считать» пульт
добавит сам:

```json
"gpu": {
  "requires": ["nvidia-smi"],
  "command": ["ffmpeg", "-hwaccel", "cuda", "-i", "{input}", "-c:v", "h264_nvenc", "-cq", "{crf}", "{out}/video.mp4"],
  "cpu_env": {"CUDA_VISIBLE_DEVICES": ""}
}
```

- `command` в блоке необязательна. Без неё на видеокарте запускается
  обычная команда — так у `stems`, где PyTorch сам берёт видеокарту.
- `cpu_env` прячет видеокарту от повтора на процессоре.

## Доступ с мака и телефона

По умолчанию пульт слушает только `127.0.0.1`. Чтобы открыть его с других
устройств, в `bind` вписывается адрес сервера в домашней сети или VPN.
**Порт в интернет не пробрасывать.** Пульт работает по HTTP без TLS, поэтому
шифрование даёт VPN. Токен вводится один раз и хранится в браузере. Кнопка
«Выйти» его стирает.

**Сейчас (2026-10-28) с мака на сервер — только SSH.** Пока так, браузер
и мост ходят через туннель:

```
ssh -N -L 8787:127.0.0.1:8787 <сервер>    # и HUB_URL=http://127.0.0.1:8787
```

Для постоянного доступа оператор подготовил скрипт для Windows, запускает
его владелец. Скрипт пробрасывает порт в WSL (`netsh interface portproxy`)
и открывает его в брандмауэре только для домашней сети и VPN. Зеркальный
режим сети WSL (`networkingMode=mirrored`) появился только в Windows 11, на
Windows 10 сервера его нет.

### Claude Code на маке

`mcp_bridge.py` — MCP-сервер на стандартной библиотеке. Он запускается на
маке рядом с Claude Code и ходит в пульт по HTTP:

```
claude mcp add home --scope user \
  --env HUB_URL=http://<адрес сервера>:8787 \
  --env HUB_TOKEN=<токен> \
  -- python3 ~/ClaudeRepo/app/mcp_bridge.py
```

Инструменты моста:

- `hub_status` — состояние сервера одним абзацем: итог и тревоги, ресурсы, свободная видеопамять, диски, службы (`detail` — полный JSON);
- `hub_tools` — список инструментов с параметрами;
- `hub_run` — запуск инструмента с ожиданием результата;
- `hub_job` — статус задачи, хвост лога, отмена;
- `hub_jobs` — последние задачи;
- `hub_files` — файлы в рабочей папке;
- `hub_upload` — файл с мака на сервер;
- `hub_download` — файл с сервера на мак, по умолчанию в `~/Downloads/hub`;
- `hub_view` — Claude смотрит картинку (кадр, контактный лист) или текст
  (отчёт громкости, субтитры, лог);
- `hub_catalog` — поиск по каталогу находок;
- `hub_resources` — бесплатные ресурсы.

Пример просьбы: «загрузи ~/Music/mix.wav на сервер, сравни с референсом
ref.wav и скажи, что поправить».

## Безопасность

- **Токен.** Все `/api/*` требуют `Authorization: Bearer <токен>`. Без
  токена отвечает только `/healthz`. Токен сравнивается за постоянное время.
- **Нет shell.** Инструменты — заранее описанные шаблоны команд. Значения
  подставляются внутрь одного аргумента и не могут добавить аргументы или
  синтаксис оболочки. Строки не могут начинаться с «-». Числа проверяются
  по границам, выбор — по списку. Путь к субтитрам, который попадает в
  фильтр ffmpeg, допускает только латиницу, цифры и `. _ - /`.
- **Файлы.** Читаются и пишутся только внутри рабочей папки: имена
  загрузок очищаются, выход из папки (`../`) отклоняется.
- **Скачивание.** Ссылки для браузера подписаны HMAC и живут 15 минут.
  Ответ идёт с `Content-Security-Policy: sandbox`. Всё, что не картинка,
  звук, видео или простой текст, отдаётся как `application/octet-stream`.
  Поэтому загруженный HTML или SVG не выполнится в пульте.
- **Интерфейс.** Строгий CSP (`default-src 'self'`), без внешних скриптов
  и шрифтов. Лог сервера не пишет токены и тела запросов.
- **Пользователи.** Пульт рассчитан на одного владельца: ролей и
  нескольких пользователей нет.

## Тесты

```
cd app && python3 -m unittest discover -s tests -v
```

Тесты поднимают настоящий сервер на свободном порту и проверяют:

- токен, раздачу статики и выход за пределы папок;
- загрузку файлов;
- все инструменты на ffmpeg, на синтетических WAV и MP4;
- скачивание с Range и подписанные ссылки;
- отмену задачи;
- голые имена файлов (`song.wav` → `inputs/song.wav`) и выход за рабочую папку;
- вариант для видеокарты: откат на процессор, `cpu_env`, «только
  видеокарта» и «только процессор»; в `tools.json` — `--no-open` у
  auto-editor, `-hwaccel` и NVENC у видеоинструментов, известные подстановки;
- `PATH` при запуске (`~/.local/bin`, `/usr/lib/wsl/lib`);
- озвучку на поддельном OpenAI-совместимом сервере (длинный текст режется
  на куски и склеивается) и на поддельном Piper (абзацы → один WAV);
- обёртку Whisper на поддельном движке: флаг языка и «auto», JSON
  faster-whisper, whisper.cpp и transformers → SRT/VTT, нарезка по словам;
- каталог, ресурсы и наборы;
- мост MCP целиком: загрузку, запуск, просмотр кадра как картинки,
  скачивание;
- обновлятор `deploy/update.sh` на временном «origin»: обновление с
  перезапуском, откат при упавших тестах без повторных попыток, остановку
  при локальных правках;
- панель «Сервер»: разбор nvidia-smi, правила тревог и гистерезис служб,
  проверки tcp/http/process, сборщик с историей и её сохранением, прогресс
  ffmpeg, удаление и очистку задач;
- интерфейс без браузера (`test_ui_static.py`, работает и на сервере):
  нет инлайн-кода и опасных API, все импорты и иконки существуют,
  `tokens.css` и копия набора совпадают с источниками;
- интерфейс в Chromium (`test_ui_browser.py`): все разделы на телефоне и
  компьютере в обеих темах — 0 FAIL по `ui_check.mjs`. Включается явно —
  `HUB_BROWSER_TESTS=1 python3 -m unittest tests.test_ui_browser`, — чтобы
  браузер на сервере (у фермы есть Chromium) не мешал обновлению.

## Docker

```
cd app && cp docker-compose.example.yml docker-compose.yml
cp config/tools.local.example.json config/tools.local.json   # вписать пути или оставить {}
HUB_TOKEN=... docker compose up -d --build
```

Образ — `python:3.12-slim` + ffmpeg + git, контекст сборки — корень
репозитория. Видеокарта пробрасывается через NVIDIA Container Toolkit
(`NVIDIA_DRIVER_CAPABILITIES` включает `video`, это нужно для NVENC).
Пути к whisper.cpp и sd.cpp внутри контейнера свои: их бинарники нужно
смонтировать или доустановить в образ.
