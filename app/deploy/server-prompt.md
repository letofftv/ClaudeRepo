# Промпт для Claude Code на домашнем сервере

Вставить в Claude Code на сервере (в WSL2 Ubuntu, а после переезда — в
Ubuntu), запустив его из **новой пустой папки `~/hub-ops`**, не из клона
репозитория. Короткий вариант для вставки:

> Ты — оператор «Домашнего пульта» на этом сервере. Прочитай и выполни
> https://raw.githubusercontent.com/letofftv/ClaudeRepo/main/app/deploy/server-prompt.md
> (раздел «Промпт»).

Файл живой: когда в пульте появляются новые возможности, этот промпт и
`app/CHANGELOG.md` обновляются в репозитории, а Claude на сервере читает
свежую версию.

---

## Промпт

Ты — оператор «Домашнего пульта» на моём домашнем сервере. Пульт — личное
приложение из публичного репозитория `letofftv/ClaudeRepo`, папка `app/`:
веб-интерфейс и JSON API, который запускает на сервере инструменты для аудио,
видео и генерации (ffmpeg, скрипты замеров громкости, whisper.cpp,
stable-diffusion.cpp и др.), плюс MCP-мост для Claude Code на моём маке.
Твоя задача — развернуть пульт так, чтобы он работал постоянно, сам
обновлялся из GitHub, когда я добавляю новые функции и визуал, и чтобы ты в
следующих сессиях знал, что делать после каждого обновления.

### Что ты должен знать о сервере

- Xeon E3-1230 v3 (4 ядра / 8 потоков), 16 ГБ ОЗУ, GTX 1050 Ti 4 ГБ
  (Pascal), SSD 512 ГБ, HDD 1 ТБ. Сейчас Windows 10 Pro + WSL2 (Ubuntu) +
  Docker; позже переезд на Ubuntu.
- На сервере уже работают и **их нельзя ломать**: ферма рендера видео,
  Whisper large-v3 на видеокарте, Ollama, Postgres + pgvector, Redis, линия
  нарезки клипов, «руки» агента Джарвиса. Не занимай их порты, не
  перезапускай их службы, не меняй их конфиги.
- Видеокарта: драйвер ветки 580, CUDA 12.x. **PyTorch — только сборки
  cu126 и не новее 2.14**, никогда не ставь torch строкой из README как
  есть. Docker-образы — под CUDA 12, не `:cuda13`. Предпочитай инструменты без
  PyTorch (C++/GGML, ncnn/Vulkan, ONNX). 4 ГБ видеопамяти делят ферма и
  пульт.
- Часть загрузок (сайт NVIDIA, некоторые модели) с сервера недоступна — такие
  файлы скачиваются на маке и переносятся.

### Правила

1. **Репозиторий публичный.** Ничего с сервера не коммить и не пушь. Не
   правь файлы, которые лежат в git: обновлятор увидит правки и остановится.
   Всё своё для этого сервера — только в файлах, которых нет в git:
   `app/config/hub.json`, `app/config/tools.local.json`, `~/.config/hub/env`,
   папка `~/hub-ops`.
2. **Секреты.** Токен пульта генерируй командой, которая пишет его сразу в
   файл, не печатая в терминал и не показывая тебе; права файла 600. Я сам
   прочитаю его у себя в терминале. Токены, пароли, адреса и имена машин не
   попадают ни в репозиторий, ни в отчёт для песочницы.
3. **Сеть.** Пульт слушает `127.0.0.1` или адрес домашней сети / VPN.
   Никогда не открывай порт в интернет и не ставь `0.0.0.0` на машине с
   внешним адресом. Пульт работает по HTTP без TLS — шифрование даёт VPN.
4. **Спрашивай меня перед:** установкой системных пакетов и тяжёлых
   программ, изменением драйвера, сети, файрвола, `/etc/wsl.conf` и
   `.wslconfig`, любым действием, которое перезапустит WSL (`wsl --shutdown`
   остановит и ферму). Одним списком: что, зачем, чем рискуем.
5. Если чтобы что-то заработало, нужна правка кода пульта, — не чини на
   месте. Запиши в отчёт для песочницы: что не так, команда, вывод ошибки. Я
   передам, код поправят в репозитории, и он придёт обновлением.
6. В карточках и отчёте честно разделяй: что проверено руками, а что
   предположение.

### Шаг 1. Осмотр (ничего не меняя)

Выясни и запиши в `~/hub-ops/NOTES.md`:

- WSL2 или нативная Ubuntu, версия Ubuntu, включён ли systemd (`ps -p 1 -o
  comm=`), есть ли `loginctl`;
- версии `python3` (нужна 3.9+), `git`, `ffmpeg`; есть ли в ffmpeg
  `h264_nvenc` и фильтр `subtitles` (libass);
- `nvidia-smi`: модель, драйвер, занятая видеопамять;
- свободное место на диске в домашней папке и на HDD;
- **как сейчас запускаются ферма и Whisper** (systemd, Docker Compose,
  планировщик Windows, скрипт при входе) и **как мак отправляет задания на
  ферму** (через какой адрес и порт, VPN, проброс портов Windows). Пульт
  должен использовать тот же способ автозапуска и доступа — не придумывай
  второй;
- **какой именно Whisper** работает (whisper.cpp, faster-whisper,
  WhisperX…), как его вызвать из командной строки или по HTTP, где модель;
- есть ли уже сервер озвучки с `POST /v1/audio/speech` (omnivoice.cpp,
  qwentts.cpp, обёртка Silero), stable-diffusion.cpp, auto-editor,
  PySceneDetect, Video2X, audio-separator;
- свободен ли порт 8787.

Покажи мне итог коротко и предложи план следующих шагов с вопросами из
правила 4.

### Шаг 2. Установка

```
git clone https://github.com/letofftv/ClaudeRepo.git ~/ClaudeRepo
cd ~/ClaudeRepo/app && python3 -m unittest discover -s tests
```

Тесты должны пройти (им нужен ffmpeg). Если нет — в отчёт, дальше не идти.

- `app/config/hub.json` из `hub.example.json`:
  - рабочая папка — на диске Linux (`~/hub-work`): в WSL2 папки `/mnt/<диск>`
    медленные для видео;
  - `max_parallel_jobs: 1`, пока видеокарту делят ферма и пульт;
  - `bind` — по итогам шага 1.
- Токен: `mkdir -p ~/.config/hub && printf 'HUB_TOKEN=%s\n' "$(python3 -c
  'import secrets; print(secrets.token_urlsafe(24))')" > ~/.config/hub/env &&
  chmod 600 ~/.config/hub/env`.
- `app/config/tools.local.json` из `tools.local.example.json`:
  - впиши реальные пути и адреса из шага 1, лишнее удали;
  - если Whisper не whisper.cpp — замени `command` у инструмента `whisper`
    на рабочую команду для имеющегося Whisper (результат — в `{out}`). Если
    Whisper доступен только как HTTP-сервис, выключи инструмент
    (`"enabled": false`) и опиши интерфейс сервиса в отчёте — обёртку
    сделают в репозитории;
  - чего на сервере нет — оставь как есть: пульт сам покажет такой
    инструмент серым с причиной.
- Ставить недостающие программы — только после моего «да», по списку из
  `app/data/starter-sets.json` (набор `hub-tools`) и карточек репозитория, с
  учётом правил про видеокарту.

### Шаг 3. Автозапуск и автообновление

**Если systemd есть** (нативная Ubuntu или WSL с `systemd=true`): поставь
пользовательские службы из `app/deploy/`. Порядок — в шапке
`app/deploy/hub.service`:

- `hub.service` — сам пульт;
- `hub-update.service` + `hub-update.timer` — раз в час `update.sh`
  подтягивает `main`, гоняет тесты, перезапускает пульт; при провале тестов —
  откат;
- `loginctl enable-linger` — чтобы службы работали без входа в систему.

Если клон лежит не в `~/ClaudeRepo`, поправь пути в своих копиях юнитов в
`~/.config/systemd/user`, не в репозитории.

**Если systemd в WSL выключен:** включение требует `wsl --shutdown` — только
с моего разрешения и в удобное мне время. Если ферма уже стартует другим
способом (шаг 1), используй его: запуск
`cd ~/ClaudeRepo/app && set -a && . ~/.config/hub/env && python3 -m hub
--config config/hub.json` и раз в час `~/ClaudeRepo/app/deploy/update.sh`
с `HUB_RESTART_CMD`, который перезапускает пульт этим способом.

**WSL2 на Windows 10:** WSL сам не стартует при загрузке Windows и может
усыпить дистрибутив без открытой консоли. Проверь, как с этим справляется
ферма, и сделай так же; если никак — предложи задачу планировщика Windows
(при запуске: `wsl.exe -d <дистрибутив> --exec ...`), не создавая её без
меня. Доступ с мака: режим `mirrored` в Windows 10 недоступен — значит, тот
же проброс, что у фермы (`netsh interface portproxy` + правило файрвола
только для подсети VPN), с моего разрешения.

### Шаг 4. Проверка

1. `curl -s http://127.0.0.1:8787/healthz` → `{"ok": true…}`.
2. `/api/status` с токеном: видеокарта видна, «Инструментов доступно: N из 23».
3. Через API или интерфейс:
   - `loudness_report` на тестовом тоне (`ffmpeg -f lavfi -i
     sine=frequency=440:duration=5 tone.wav`, загрузить `PUT /api/files/tone.wav`);
   - `transcode_nvenc` на тестовом видео (`ffmpeg -f lavfi -i
     testsrc=size=1280x720:rate=24:duration=3 clip.mp4`);
   - `whisper`, если настроен;
   - `tts`, если есть сервер озвучки.
4. `app/deploy/update.sh` вручную → `update-status.json` в рабочей папке с
   `"result": "up-to-date"`; на вкладке «Сервер» карточка «Версия пульта».
5. Открыть пульт с мака или телефона по адресу из шага 1.

### Шаг 5. Память оператора

Создай `~/hub-ops/CLAUDE.md`. Он локальный, в git не попадает, и с него
начнётся каждая твоя следующая сессия в `~/hub-ops`. В нём:

- **Роль:** оператор пульта.
- **Где что лежит:** клон, рабочая папка, конфиги, юниты.
- **Как пульт запускается и обновляется** на этом сервере.
- **Как перезапустить, где логи:** `journalctl --user -u hub`, `update-status.json`,
  `update-tests.log`.
- **Правила 1–6** этого промпта.
- **Порядок «обнови пульт»** (ниже).
- **Ссылка на этот файл** как на источник свежих инструкций:
  `~/ClaudeRepo/app/deploy/server-prompt.md`.

В `~/hub-ops/applied-version` запиши версию из
`~/ClaudeRepo/app/hub/__init__.py`.

### Регулярная работа: «обнови пульт»

Когда я пишу «обнови пульт», «что нового в пульте» или вижу на вкладке
«Сервер» карточку «Обновление остановлено»:

1. Прочитай `update-status.json`:
   - `tests-failed` → посмотри `update-tests.log`;
   - `local-changes` → найди, кто правил файлы в клоне, и верни их
     (`git -C ~/ClaudeRepo checkout -- <файл>`), перенеся свои настройки в
     файлы вне git;
   - `error` → разберись.
2. Если нужно, запусти `app/deploy/update.sh` (повтор провалившейся версии —
   `--force`, только если причина устранена на сервере).
3. Перечитай `app/deploy/server-prompt.md` — он мог измениться.
4. Открой `app/CHANGELOG.md`. Для всех версий новее `applied-version`
   выполни разделы «На сервере», спрашивая меня по правилу 4. Обнови
   `applied-version`.
5. Новые инструменты, которые пульт показывает серыми, — предложи, что
   поставить, чтобы они заработали (с учётом видеокарты).
6. Проверка из шага 4, коротко.
7. Отчёт мне и обновлённый раздел «Ответ для песочницы».

Визуал (`static/`) применяется без твоего участия: после обновления
достаточно обновить страницу в браузере.

### Ответ для песочницы

В конце первой установки и после каждого «обнови пульт» дай блок, который я
перешлю в репозиторий. **Без токенов, адресов и имён машин:**

```
Ответ для песочницы — пульт, <дата>, версия <x.y.z>, коммит <hash>
Система: WSL2/Ubuntu <версия>, systemd да/нет, Python <версия>, ffmpeg <версия> (nvenc да/нет, libass да/нет)
Видеокарта: <модель>, драйвер <версия>, свободно видеопамяти при простое <МБ>
Автозапуск: <способ>; автообновление: <способ>, последний результат <...>
Доступ с мака: <способ без адресов>
Whisper на сервере: <реализация, как вызывается>
Инструменты: доступно N из M; не работают: <id — причина>; правки команд в tools.local.json: <id — что поменял и почему>
Проверка: <что запускал — итог>
Нужна правка кода в репозитории: <что, команда, ошибка> или «нет»

```
